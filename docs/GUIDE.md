# Руководство AntiAFK

## Установка

1. Открой [Releases](https://github.com/BxdiS/antiafk/releases).
2. Скачай **`AntiAFK.exe`** из последнего релиза.
3. Запусти — установка не нужна, приложение портативное (один файл, без прав администратора).

> Настройки, лог и прогресс цикла хранятся только в памяти процесса и сбрасываются при каждом запуске — на диске приложение ничего не оставляет ни во время работы, ни после закрытия (кроме кратковременных временных файлов на пару секунд во время применения обновления).

## Управление (трей)

| Пункт | Действие |
|-------|----------|
| Запустить / Остановить | Старт и пауза бота. Состояние цикла сохраняется до перезапуска приложения |
| Обновить | Появляется при доступном обновлении. Устанавливает скачанный апдейт (замещает сам себя и перезапускается) |
| Настройки | Язык (RU/EN), путь к лаунчеру игры — действуют до следующего запуска |
| Открыть лог | Живой журнал текущей сессии (в памяти, не файл) |
| Выход | Полное закрытие приложения |

### Обновления

- Проверка при запуске и каждые N часов (см. конфиг, по умолчанию 6).
- Источник — последний **опубликованный** (не draft, не pre-release) релиз на GitHub.
- Скачивание в фоне; синяя иконка в трее при доступном апдейте.
- По клику «Обновить»: `AntiAFK.exe` заменяет сам себя новой версией и перезапускается. Временные файлы обновления удаляются автоматически сразу после применения.

## Конфигурация

Настройки задаются через трей → **Настройки** и живут только в памяти текущего запуска (на диск не пишутся). Пример полей конфигурации — [config.example.json](config.example.json), используется как справка по структуре, а не как реальный файл на диске.

- `launcherPath` — пустой = авто-поиск лаунчера в стандартных путях Windows.
- Координаты UI и тайминги зашиты в код, не редактируются через конфиг.

## Сборка из исходников

```bash
git clone https://github.com/BxdiS/antiafk.git
cd antiafk
dotnet build src/AntiAfk.App/AntiAfk.App.csproj
dotnet run --project src/AntiAfk.App/AntiAfk.App.csproj
```

### Структура проекта

```
src/
  AntiAfk.Core/           — движок, координаты, состояние
  AntiAfk.Infrastructure/ — WinAPI, экран, конфиг (in-memory), лог (in-memory)
  AntiAfk.App/            — трей + настройки (WinForms) + обновления
```

## Релизы (для разработчика)

CI запускается при push тега `v*`.

```bash
git push origin main
git tag v1.0.1
git push origin v1.0.1
```

GitHub Actions:
1. Собирает приложение как единый Native AOT `.exe` (win-x64, без .NET runtime рядом — самодостаточный нативный бинарник).
2. Считает SHA-256 чек-сумму.
3. Публикует релиз **сразу** (не draft) с автоматически сгенерированными release notes.

> В отличие от прежней Velopack-схемы, релиз публикуется автоматически — не нужно вручную заходить в GitHub и жать Publish. Именно забытый шаг публикации был причиной "автообновление не работает" в старой схеме.

### Файлы в GitHub Release

| Файл | Нужен пользователю? | Зачем |
|------|----------------------|-------|
| `AntiAFK.exe` | **Да** | Единственный файл, который нужен пользователю |
| `AntiAFK.exe.sha256` | Нет | Чек-сумма для проверки целостности |

### Release notes

Автогенерация GitHub даёт список коммитов. Если нужен более читаемый текст — отредактируй релиз на GitHub после публикации. Пример — [docs/RELEASE_NOTES.example.md](RELEASE_NOTES.example.md).

## Подпись кода (SignPath)

`AntiAFK.exe` не подписан, поэтому Windows SmartScreen может показывать предупреждение при первом запуске — это ожидаемо для непонятного публике бинарника и не связано с портативностью/AOT.

1. Проект под [GPL-3.0](../LICENSE) — OSI-совместимая лицензия, требование SignPath.
2. Подать заявку: [signpath.org](https://signpath.org/).
3. Подключить подпись в CI шагом после `dotnet publish`, подписывающим `publish/AntiAFK.exe` напрямую (без `vpk --signTemplate`, который относился к прежней Velopack-схеме).

SignPath **не подписывает** проекты с проприетарными или non-OSI лицензиями.

## Troubleshooting

| Проблема | Решение |
|---------|---------|
| Игра не найдена | Окно процесса GTA5.exe или заголовок мультиплеер-клиента с версией в скобках |
| Обновления не работают | Проверь, что последний релиз на GitHub опубликован (не draft/pre-release) и содержит `AntiAFK.exe` |
| Workflow не запустился | Тег должен начинаться с `v` |
| Настройки "потерялись" после перезапуска | Ожидаемое поведение — портативная версия ничего не сохраняет на диск между запусками |
